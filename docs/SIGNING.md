# امضای ثابت و انتشار به‌روزرسانی

برنامهٔ نصب‌شده باید با کلید خصوصی اصلی همین محصول به‌روزرسانی شود. اثر انگشت عمومی گواهی در `signing-certificate.sha256` ثبت شده است؛ کلید خصوصی هرگز نباید وارد ریپو یا چت شود. صف پیام، مخاطبان و زمان‌بندی با نصب نسخهٔ جدید حفظ می‌شوند، به شرط آن‌که امضای APK یکی باشد و کاربر برنامه را حذف نکند.

کلید خصوصی در بستهٔ امن قبلی با نام `preserved-signing.p12` و رمز همان بسته قرار دارد. این دو Secret را در GitHub → Settings → Secrets and variables → Actions تنظیم کنید:

| نام Secret | مقدار |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | محتوای base64 فایل `preserved-signing.p12` |
| `ANDROID_SIGNING_PASSWORD` | رمز کی‌استور بستهٔ امن |
| `APP_RELEASE_UPLOAD_TOKEN` | توکن تصادفی فقط برای بارگذاری APK |

در متغیرهای محیطی سرویس Hamravesh، `APP_RELEASE_UPLOAD_TOKEN_SHA256` باید برابر SHA-256 همان توکن باشد. توکن خام فقط در GitHub و hash آن فقط در تنظیمات سرور قرار می‌گیرد؛ هیچ‌کدام را در چت یا فایل‌های ریپو نگذارید. روش دقیق تنظیم این موارد در [راهنمای Hamravesh](HAMRAVESH.md) آمده است.

پس از پاس‌شدن تست‌ها و Lint، GitHub Actions کلید اصلی را موقتاً بازیابی می‌کند، APK را می‌سازد و اثر انگشت، شناسهٔ بسته و نسخه را بررسی می‌کند. فقط APK تأییدشده به `/data/app-releases` روی دیسک پایدار سرور می‌رود. GitHub Release شامل یادداشت تغییرات و پیش‌نمایش است و APK یا artifact باینری ندارد. برنامه manifest نسخه را از سرور می‌خواند و پیش از بازکردن نصب‌کننده، SHA-256 و امضای APK را با نسخهٔ نصب‌شده تطبیق می‌دهد.

اگر Secretهای امضا یا بارگذاری تنظیم نشده باشند، آزمون‌ها می‌توانند موفق شوند اما APK و تگ Release ساخته نمی‌شوند. این کار از انتشار APK ناسازگار یا نسخه‌ای که هنوز روی سرور در دسترس نیست جلوگیری می‌کند. کلید تازه نسازید؛ تغییر کلید باعث می‌شود نسخهٔ موجود روی گوشی به‌صورت به‌روزرسانی نصب نشود.
